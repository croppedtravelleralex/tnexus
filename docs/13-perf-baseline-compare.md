## 1. Python `:8012` 基线（2026-07-20 记录）

| 维 | 当时记录 | 2026-07-26 实测 | 判定 |
|----|---------|----------------|------|
| 空闲 CPU | ~0.5–0.7% | **98.5%**（10 个 submit worker GIL 争抢） | ❌ 偏两个数量级 |
| Mem | ~160–230 MiB | **224 MB** | ✅ 吻合 |
| 文本成功耗时 | ~5.5–13.4s（3/4 ok） | p50 6.32s / p95 12.05s（n=2,735，成功率 68.8%） | ✅ 吻合 |
| 生图成功耗时 | ~43–54s（3/4 ok） | 43–111s | ⚠️ 原样本仅 4 次 |
| schedulable / clearance | 6 / false | — | — |

CPU 基线错误的后果：以「空闲 0.5%」为参照推导出的所有 Rust 收益比例失去意义。
真实基线是**单核跑满**，而这 98.5% 中绝大部分是 GIL 争抢的纯浪费 —— 反而说明重写空间比原估更大。

## 2. Rust 预估（**已作废**）

原表：

| 维 | 保守（helper） | 理想 | MVP `:8013` | 全量 |
|----|---------------|------|-------------|------|
| RSS | −20%~−40% | −50%~−70% | （空） | （空） |
| CPU 高负载 | −10%~−25% | −30%~−50% | （空） | （空） |
| 同机并发 | ×1.3–2.0 | ×2–3 | （空） | （空） |
| 生图 E2E | +0%~+15% | +0%~+10% | （空） | （空） |

作废理由（逐条见 [26](26-perf-measured-20260726.md) §7）：

| 项 | 作废原因 |
|----|---------|
| RSS 下降 | Rust 是**加**在 Python 前面的一层，Python 一个进程没少。系统总 RSS **+5.2MB** |
| CPU 下降 | 98.5% 全在 Python 的 10 个 submit worker 里，`crates/` 无对应实现；Rust 多加一次 JSON 往返，**净增** |
| 并发提升 | 上限是 anyio 池 40 × 同账号锁串行 × GIL，Rust `Semaphore(3)` 比三者都松，**不是瓶颈** |
| E2E | 43–111s 全是上游等待，Rust 参与 <1ms。**该指标与网关语言无关** |

MVP/全量两列从未被填充 —— 说明这些数字从提出到作废，**没有任何一次实测尝试**。
