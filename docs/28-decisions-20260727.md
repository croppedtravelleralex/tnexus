### 1.4 鉴权模型 → **先对齐 Panda；超越 Panda 的才做增强**

**原则**：鉴权以 Panda 现网为唯一验收标准。任何 Panda 没有的能力（JWT 会话、Web UI 登录、admin/member 角色门禁等）一律归入**后续增强**，不在对齐阶段强制启用或阻塞部署。

| 层 | Panda 现网 | 本仓对齐目标 | 增强（后续） |
|----|-----------|-------------|-------------|
| `:8012` 主面 | API key（`Authorization: Bearer` → `auth_service.authenticate`） | R2 切流前实现同等语义 | — |
| `:8013` Rust face | **`AUTH_DISABLE=1`（无鉴权）** | 部署默认复现此行为（见 §2 env） | JWT + 角色门禁（`crates/auth` 已有代码，**不默认开**） |
| Helper `:19001` | 2026-07-26 起 `X-Helper-Token` fail closed | ✅ 已对齐 | — |
| Web UI | Panda 无 dashboard 鉴权面 | 不阻塞 `:8013` 对齐 | `web/` + `gws_session` cookie（需 `AUTH_DISABLE=0` + 静态托管） |

| 项 | 内容 |
|----|------|
| **决议** | ① **对齐阶段**：`:8013` = 无鉴权（`AUTH_DISABLE=1`）；R2 替换 `:8012` = API key；② **增强阶段**（Panda 对齐完成之后）：JWT/Web UI/用户管理可作为可选能力上线，不得与 API key 语义互斥（同 `Authorization: Bearer` 须能区分或分路由） |
| **依据** | [docs/25](25-panda-vs-rust-20260726.md) §3.1；用户确认 2026-07-27：「鉴权先对齐 panda，超越 panda 作为后续增强」 |
| **落地** | `AuthMode`：`disabled` / `api_key` / `jwt`；`GATEWAY_AUTH_KEY` 对齐 `:8012`；`PANDA_ALIGN=1` bringup 预设 |

## 2. Panda 部署参数速查（复现现网 `:8013`）

```bash
PANDA_ALIGN=1 bash scripts/panda_bringup_rust_face.sh
```

或：

```bash
set -a && source deploy/panda-8013.env.example && set +a
bash scripts/panda_bringup_rust_face.sh
```

等价 env：

```bash
AUTH_DISABLE=1 \
IMAGE_ENABLED=1 \
GATEWAY_LISTEN=0.0.0.0:8013 \
HELPER_INTERNAL_TOKEN=<from secrets/helper_token> \
bash scripts/panda_bringup_rust_face.sh
```

`:8012` API key 对齐（增强前、替换 R2 前自测）：

```bash
AUTH_DISABLE=0 \
GATEWAY_AUTH_KEY=<config.auth_key> \
GATEWAY_LISTEN=127.0.0.1:8013 \
HELPER_INTERNAL_TOKEN=... \
./target/release/gptimage-gateway-rs
```

> bringup 脚本默认 `AUTH_DISABLE=0` / `IMAGE_ENABLED=0` / `127.0.0.1:8013`（安全缺省）。
> `PANDA_ALIGN=1` 一键覆盖为 Panda 现网；公网无鉴权组合需该标志或 `ALLOW_INSECURE_PUBLIC=1`。
