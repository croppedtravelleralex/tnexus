### 2.1 「禁用用户」这个安全控制实际不生效

[crates/gateway/src/auth_routes.rs:175](../crates/gateway/src/auth_routes.rs) 的 `require_auth` 只做 `verify_token`，从不回查 users 表的 `disabled` / `role`，也无 `jti` 吊销表。

- 管理员禁用某用户后，对方仍可用原 JWT 访问全部接口，最长 24h（默认 TTL 86400s）
- 降权同样无效
- `logout`（`:105`）仅下发 `Max-Age=0` 空 cookie，服务端不作废 token，"登出"无实际效果
- `/api/auth/me`（`:118`）不检查 `disabled` 直接回 200

### 2.2 脱敏门禁是构造性的虚假保证

[scripts/check_runlog_desense.py:10](../scripts/check_runlog_desense.py) 把扫描范围写死为 `<repo>/data/runlogs`，而 [.gitignore:4](../.gitignore) 正是 `data/runlogs/*` —— 干净检出下该目录只有 `README.md`，门禁**必然**打印 `DESENSE_OK`。真实日志在 panda 的 `/root/gptimage/data/runlogs`、`/root/gptimage-gateway-rs/data/runlogs` 与 `rust-gateway.log` 从未被扫过一眼。且该脚本**零调用方、无 CI**。

正则本身（`Bearer\s+\S+|eyJ[A-Za-z0-9_-]{20,}\.[A-Za-z0-9_-]{10,}`）另有漏网：

| 漏掉的形状 | 原因 |
|-----------|------|
| `eyJhbGciOiJIUzI1NiJ9.…`（最常见的 HS256 头） | 头部仅 17 字符，不满足 `{20,}` |
| `bearer …` 小写 | 无 `re.IGNORECASE` |
| `sk-proj-…` / `sk-ant-…` | 完全没有 `sk-` 模式 |
| `http://user:pass@host` | 无内联凭据模式 —— 而这正是 S-2 返回的字符串 |
| 邮箱 / `oai-device-id` / cookie 名 / 长 base64 | 均无对应模式 |

结构性缺陷：`:22` 跳过 `.gz`（轮转常态即压缩）；`:25` 用 `errors="ignore"`；`:26` 吞 `OSError` 后 `continue`，不可读文件被当作干净。

### 5.5 sys.path 注入 + chdir 的工程风险

1. **版本不可锁**（最重）：无 submodule、无 pin、无 commit SHA。`SOURCE.md` 只写路径不写版本，生产树一次重构就静默改变 helper 行为，`git bisect` 无从下手。
2. **命名空间污染**：`sys.path[0]` 使 gptimage 的 `services/`、`utils/`、`scripts/`、`api/` 四个通用名包优先于 site-packages。
3. **`os.chdir` 在 import 期执行**：pytest 收集阶段就会改掉整个进程 CWD —— 这是 **Python 侧零测试的结构性原因**。
4. **共享可变状态**：PY-2 已证实 helper 能污染生产 `config.json`；号池状态同理。
